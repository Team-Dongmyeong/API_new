## 1. 현재 상태

- **SBERT(키워드 분류)**: `snunlp/KR-SBERT-V40K-klueNLI-augSTS` 파인튜닝, 148개 결합 라벨(대분류\|\|중분류\|\|소분류) 분류, `BatchHardTripletLoss` 사용. Held-out 평가 완료 — 대분류 95.95%/중분류 72.03%/148-way 57%(macro-F1 0.42). 약점은 식/음료·디자인 계열에 집중(데이터 절대량 부족이 원인으로 결론). `SentenceLabelDataset` 재학습(`_v2`) 시도했으나 개선 없음 확인.
- **KcELECTRA(감정 분류)**: `beomi/KcELECTRA-base-v2022` 파인튜닝, 7-class 한국어 구어체 감정 분류. **재학습 및 held-out 평가 완료** (가중치 유실 사고 이후 처음부터 재학습, 결과는 아래 참고).
  - 전체: accuracy 60.4% / macro-F1 0.56 / weighted-F1 0.60
  - 잘 맞추는 감정: 중립(F1 0.76), 행복(F1 0.70), 슬픔(F1 0.62)
  - 약한 감정: 혐오(F1 0.40), 놀람(F1 0.42), 공포(F1 0.47) — 서로 뉘앙스가 겹치는 부정적 감정끼리 혼동
  - 특이사항: 슬픔은 recall 0.75로 높지만 precision 0.53로 낮음 — 슬픔이 아닌 발화도 슬픔으로 오판하는 경향 있음. 취업 상담 챗봇 특성상 사용자가 힘든 얘기를 자주 하므로, 챗봇이 슬픔 쪽으로 살짝 치우쳐 반응할 수 있다는 점 참고.
  - 결론: 중립/행복/슬픔은 자신 있게 사용 가능, 혐오/놀람/공포는 보수적으로 취급(SBERT의 대분류-vs-148way 취급 방식과 동일한 원칙).
- **RAG 지식베이스 범위**: 4개 소분류(역량부족/취업진로/면접준비/자기소개서) 중 **역량부족·취업진로 2개만 구조화 데이터로 구축**. 면접·자소서는 RAG 없이 GPT-4o mini가 감정 분석 결과와 결합해 직접 답변 생성.
- **자소서/면접 프롬프트 설계**: 고용24 자소서가이드에서 추출한 5가지 질문 유형 프레임워크를 GPT 시스템 프롬프트에 고정 반영하는 설계 완료, 실제 연동은 미착수.
- **RAG 인프라**: Supabase + pgvector 계획만 있고 코드 미착수. 프론트엔드 완성 후 연결 예정.
- 세부 근거·수치는 Project Knowledge의 `AI_모델_학습_및_검증_전략.md`, `RAG_데이터_전략_논의_정리.md`, `자소서_답변_생성_프롬프트_설계.md`, `최종 방향 정리병철이 전달 문서.md` 참고.

## 3. 주요 결정 사항

- SBERT 재학습으로도 식/음료·디자인 약점이 개선되지 않아, 다음 단계는 **해당 카테고리에 한정한 GPT 표적 데이터 증강**으로 확정.
- RAG는 "사실 정보가 존재하는 영역(역량부족·취업진로)에만 적용"으로 범위를 좁힘 — 차별화 근거는 "RAG 완비"가 아니라 "사실기반/코칭기반 하이브리드 설계" 자체.
- 면접·자소서는 구조화 데이터셋 없이 GPT-4o mini 프롬프트 엔지니어링(5유형 프레임워크 고정 반영)으로 대응.
- 공개 데이터 활용 우선순위: 임금직업포털 → NCS 직업기초능력 → NCS 자가진단. 고용24 자소서가이드는 RAG 데이터로 만들지 않음.
- KcELECTRA는 중립/행복/슬픔 위주로 신뢰하고, 혐오/놀람/공포는 보수적으로 취급하기로 결정(SBERT와 동일한 원칙 적용).
- **Google Drive 파일 관리 원칙 확정**: `optimizer.pt`, `model.safetensors`, `pytorch_model.bin`은 절대 용량 정리 대상에서 제외. 용량 정리 필요 시 지우기 전에 먼저 확인.
