## 2. 이번에 추가한 기능

- **재정경제부_공공기관 채용정보 조회서비스** (data.go.kr, 서비스ID 15125273) 연동
- `BASE_URL = https://apis.data.go.kr/1051000/recruitment`
- 서비스키는 하드코딩하지 않고 `job-fetch/service_key.txt`에서 읽어오도록 분리 (`.gitignore` 등록 완료)
- `job-fetch/fetch_jobs_to_mock.py`: API 호출 → 가공 → `src/mocks/jobsReal.js` 자동 생성
- `mocks/jobs.js`는 더미데이터를 완전히 지우고 `jobsReal.js`를 그대로 재수출(`export { REAL_JOBS as DUMMY_JOBS } from './jobsReal.js'`)하도록 변경
- **(2026-10-08 기준) 이 방식은 완전히 폐기됨 — 2.17 참고**

### 2.2 채용공고 수집 개수 확대

- 대분류 하나당 NCS 코드를 **여러 개** 매핑해서 합쳐 가져오도록 개선 (예: 디자인 = 문화예술디자인방송 + 섬유의복)
- `recrutPblntSn` 기준 중복 제거

### 2.3 실제 채용 공고 URL 연결
- API 응답의 `srcUrl`을 `job.url`로 매핑
- 공고 카드 제목 클릭 시 새 탭으로 실제 채용 페이지 이동
- 카드 하단 "지원하러 가기" 버튼도 동일한 URL로 연결

### 2.4 채용공고 리스트 페이지네이션
- 공고 10개 이상일 때 하단에 이전/번호/다음 버튼 노출
- 상단 스마트픽·필터 영역은 고정, **리스트 영역만** 페이지 전환되도록 구현
- **(2026-10-06 개선) 페이지 번호도 10개 단위로 묶어서 표시** — 공고가 많아 전체 페이지가 10개를 넘어가도 번호가 한 줄에 다 늘어서지 않고, 현재 보고 있는 페이지가 속한 묶음(1~10, 11~20...)만 보여줌. 묶음 양 끝에 «/» 버튼을 추가해서 통째로 다음/이전 묶음으로 건너뛸 수 있음

### 2.5 채용공고 리스트 필터 — 대분류 → (NCS 세부 분류) → 경력
- 처음엔 "대분류 → 세부직무 → 경력" 3단계 계단식(드릴다운) 필터로 만들었으나, 세부직무는 공고 **제목 키워드로 추정**한 값이라 정확도가 낮고(공공기관 공고는 "일반행정" 같은 포괄적 제목이 많아 대부분 "직무공통"으로 떨어짐), 리스트를 **걸러내는** 용도로 쓰기엔 신뢰도가 부족하다고 판단 → 세부직무 필터 단계는 제거
- 대신 **대분류 안에서 실제로 섞여 있는 NCS 코드 차이**를 필터로 추가함. 예를 들어 '디자인' 대분류는 NCS상 "문화예술디자인방송"과 "섬유의복"(패션디자이너) 두 코드로 수집되는데, 이건 공고 제목을 추정한 게 아니라 **실제로 어떤 NCS 코드로 그 공고를 가져왔는지**를 그대로 반영한 값이라 필터로 써도 안전함
  - 새 필드 `job.ncsGroup` (예: `'문화예술디자인방송'`, `'섬유의복'`) 추가
  - `constants/jobCategories.js`에 `NCS_GROUPS_BY_CATEGORY` 추가 — 대분류별로 이 세부 분류 목록을 정의
  - NCS 코드가 1개뿐인 대분류(IT/SW, 공공·복지)는 나눌 게 없어서 이 필터 자체가 안 보임. 코드가 2개인 대분류(디자인, 식·음료, MD/상품기획)를 선택했을 때만 "{대분류} 세부 분류" 칩이 추가로 나타남
  - 최종 필터 체계: **대분류(신뢰도 高) → NCS 세부 분류(신뢰도 高, 일부 대분류에서만) → 경력**
- 세부직무(37개) 단위 분류/추천은 **스마트픽에서만** 참고용(근사치)으로 계속 사용 — 리스트 필터에서는 빠짐

### 2.6 세부직무 자동 분류 로직 & `/detail` 엔드포인트 조사
- `classify_subjob()`: 공고 제목의 키워드를 매칭해 37개 세부직무 중 하나 또는 "직무공통"으로 분류
- 공공기관 공고는 행정·관리 성격이 강해 구체적 직무 키워드가 잘 안 나타나는 구조적 한계 확인
- API가 제공하는 NCS 코드는 **대분류 수준까지만** 제공되어, NCS 세분류 기반 재매핑은 기술적으로 불가능함을 확인
- `/detail`(상세조회) 엔드포인트도 직접 호출해 확인해봤으나, 필요한 파라미터를 아직 못 찾았고(`필수요청 파라미터가 없음` 에러) `/list` 응답에 이미 상세조회에서나 나올 법한 텍스트 필드(자격요건/우대사항/전형절차 등)가 전부 들어있는 걸 확인함 → 한 공고 안에 여러 직무가 섞인 경우(예: 한국디자인진흥원 공고)에도 "백엔드/프론트엔드/웹개발자" 같은 **직무 라인 단위의 구조화된 데이터는 어느 엔드포인트에도 없을 가능성이 높음** → 더 이상 추적하지 않기로 함(다만 다건 NCS 코드 태깅 자체는 실제로 잘 동작하는 것을 확인 — 한 공고에 NCS 코드 7개가 붙는 사례 확인됨)

### 2.7 검토했지만 전부 기각된 대체 데이터 소스
- **마이다스 에이치닷(H.Place) API**: 고객사 전용 API로, 외부 개발자 신청 경로가 없어 기각
- **워크넷/고용24 채용정보 API** (data.go.kr 3038225): 실제 신청해서 확인한 결과 **개인회원은 아예 사용 불가**("개인회원은 사용할 수 없는 OPEN-API입니다"). 개인회원이 쓸 수 있는 채용행사/공채속보/공채기업정보 API는 공고 단위 구조화 데이터를 제공하지 않아 대체 불가. **완전히 기각**
- **원티드(Wanted) OpenAPI**: 신청 후 몇 달 대기 끝에 **거절 통보 받음**
- **사람인 API**: 신청 후 몇 달째 무응답 — 사실상 거절로 추정됨

### 2.8 현재 결론
- **재정경제부_공공기관 채용정보 API가 사실상 유일하게 쓸 수 있는 실제 데이터 소스**로 확정됨
- 민간기업 채용공고(원티드/사람인/잡코리아/워크넷 전부 기각·거절)를 추가로 확보할 경로가 현재는 없음 → 서비스 범위는 당분간 "공공기관 채용공고"로 한정
- 팀 논의 결과, 원래 만들던 인앱 채용공고 리스트(대분류/필터/스마트픽) 방식을 그대로 유지하기로 확정 (외부 사이트로 리다이렉트하는 "관련 채용정보 보기" 버튼 방식은 보류)

### 2.9 스마트픽 리뉴얼 — 추천 직업 3개 + 적성검사·채팅 연동 포인트
- 스마트픽이 추천하는 단위를 "대분류 1개"에서 **"세부직무 3개"**(`{subJob, category}` 배열)로 변경
- `PreferenceContext.jsx`: 적성 검사 결과 70% + 채팅 분석 결과 30% 가중치로 대분류/세부직무 점수를 합산(기존 60:40에서 변경)해 `recommendedJobs`(추천 직업 TOP3)와 `preferredCategory`(마이페이지용, 기존 로직 그대로 하위호환 유지)를 동시에 계산
- 실제 적성검사/채팅 분석 결과를 연동할 때 호출할 함수를 미리 만들어둠: `setTestSubJobResult(...)` / `setChatSubJobResult(...)`
- (2026-10-08 기준) 진단 퀴즈 쪽은 2.12에서 실제 연동 완료. 채팅 쪽은 "대화 기능"은 동작하지만 "분류 단계"는 아직 — 2.17 참고

### 2.12 스마트픽 2차 작업 (2026-10-07) — 진단 퀴즈 세부직무 연동 · 마이페이지 동기화 · UI 다듬기
오늘 스마트픽 쪽에서 요청받은 세 가지를 전부 반영함.

**① 헤더 "진단하기" 퀴즈가 세부직무까지 계산하도록 확장**
- 기존엔 `PreferenceQuiz.jsx`(헤더의 "진단하기" 버튼으로 여는 5문항 간단 진단)가 대분류만 집계해서 `setTestResult`만 호출 — 그래서 이 퀴즈를 풀어도 마이페이지 "선호 추천 분야"만 바뀌고, 스마트픽이 쓰는 "추천 직업 3개"(세부직무 단위)는 Jobs.jsx의 수동 테스트 칩으로만 바뀔 수 있었음
- 각 문항의 선택지 25개(5문항 × 5개)에 대표 세부직무를 하나씩 매칭해둠(예: "새로운 프로그래밍 언어나 툴 익히기" → 백엔드개발자, "맛있는 음식 레시피 연구하기" → 요리사 등) — 질문 자체를 37개로 늘리기엔 너무 길어져서, 질문 내용과 제일 가까운 세부직무 1개씩을 대표로 연결한 근사치. 정확한 매칭은 추후 실제 KcELECTRA/SBERT 결과로 대체되면 자연히 개선됨
- 퀴즈 제출 시 대분류 벡터 + 세부직무 벡터를 같이 계산해서 `onSubmit(categoryVector, subJobVector)`로 넘기고, `Header.jsx`가 이를 받아 `setTestResult(categoryVector)`와 `setTestSubJobResult(subJobVector)`를 둘 다 호출하도록 변경
- 결과: 헤더에서 "진단하기" 퀴즈를 실제로 풀면 마이페이지 선호 추천 분야 + 스마트픽 추천 직업 3개가 **동시에, 실제 진단 흐름으로** 바뀌는 걸 확인할 수 있음

**② 마이페이지 "추천직업" 탭을 채용공고 스마트픽과 동일한 데이터로 연결**
- 기존엔 `MyPage.jsx`의 "추천직업" 탭이 `JOB_MATCHES`라는 완전히 별개의 더미데이터 3건(백엔드 엔지니어 94% 등, 고정값)을 보여주고 있어서 스마트픽이 뭘 추천하든 이 탭은 전혀 안 바뀌는 상태였음
- `JOB_MATCHES` 더미데이터를 삭제하고, `usePreference()`에서 `recommendedJobs`/`hasSubJobPreferenceData`/`combinedSubJobScores`를 가져와 그대로 렌더링하도록 교체 — 이제 두 화면이 **같은 PreferenceContext 값을 구독**하기 때문에, 진단·채팅 결과가 바뀌면 마이페이지 추천직업 탭과 채용공고 스마트픽이 항상 동시에 같은 3개를 보여줌(요청하신 "마이페이지 바뀌면 스마트픽도 똑같이" 요건)
- 매칭률(%)도 더미 숫자 대신 `combinedSubJobScores`에서 실제로 계산해서 표시
- 아직 진단 결과가 없는 상태(검사·채팅 둘 다 0점)면 더미 카드 대신 "아직 진단 결과가 없어요" 안내로 바뀜
- "공고 확인하기" 버튼도 `/home/jobs?job={세부직무}` 형태의 딥링크로 바꿔서, 누르면 채용공고 탭에서 그 세부직무가 속한 대분류 필터가 자동으로 선택된 상태로 열림(Jobs.jsx에 이미 있던 딥링크 기능 재사용)

**③ 스마트픽 UI 다듬기**
- 추천 직업 3개 칩에 매칭률(%) 배지 추가 — 어떤 직업이 왜 1순위인지 수치로 보여줌
- (개발용) 수동 테스트 칩 블록을 `<details>`로 접어서 기본적으로는 숨겨두고, 펼쳤을 때만 보이게 변경(2026-10-08에 완전히 제거됨 — 2.17 참고)
- 공고 카드에 "{세부직무} 매칭" / "관련 공고" 배지를 추가해서, 선택한 추천 직업과 정확히 일치하는 공고인지 아니면 3건을 채우기 위한 관련 공고인지 구분되게 함
- 장식용으로만 쓰이던 Heart 아이콘(클릭 안 되는데 클릭 가능한 것처럼 보임) 제거

### 2.13 스마트픽 — 공고 URL 연결 + 선호 근무 지역 우선배치 (2026-10-07)

  - 지역이 일치하는 카드에는 "📍 선호 지역" 배지를 추가로 표시해서 왜 그 공고가 위로 왔는지 보이게 함

### 2.14 공고 URL이 "없음"/"." 같은 텍스트라서 눌러도 안 넘어가던 문제 수정 (2026-10-07)
- 한전KDN 공고 등 일부 공고에서 "URL을 눌렀는데 아무 데도 안 넘어간다"는 증상 확인 → 원인은 재정경제부 API의 `srcUrl` 필드가 실제 링크 대신 `"없음"`, `"없음."`, `"해당없음"`, `"."` 같은 안내 텍스트로 오는 경우가 있었음(해당 공고 173건 중 11건, 전부 한전KDN·일용직 계열 — 기관이 공식 지원 URL 대신 문의처만 남긴 경우로 보임). 기존 코드는 "값이 비어있지 않으면 링크"로 판단해서 이런 텍스트도 그대로 `href`에 넣어버렸음
- `clean_url()` 함수 추가 — `http`로 시작하는 값만 진짜 URL로 인정하고, 나머지(빈 문자열 포함 "없음"류 전부)는 빈 문자열로 정리해서 `job.url`에 넣음 (이 로직은 2.17에서 `main.py`로 그대로 포팅됨)
- **`src/pages/app/Jobs.jsx`**: `isValidJobUrl()` 함수 추가해서 프론트에서도 한 번 더 같은 기준(`http`로 시작하는지)으로 검증 — 스마트픽 카드, 채용공고 리스트 제목 링크, "지원하러 가기" 버튼 3곳 전부 이 함수로 교체

### 2.15 스마트픽 — 선호 근무 지역 × 선호 추천 분야(대분류) 동시 적용 (2026-10-07)

  1. 세부직무까지 정확히 일치
  2. 같은 대분류(선호 추천 분야)지만 세부직무는 다름 — **여기서부터 지역·분야가 같이 맞춰짐**
  3. (1·2를 합쳐도 3건이 안 채워질 때만) 그 외 전체 공고 — 스마트픽이 항상 3건을 보여주기 위한 최후 보루, 보통 거의 안 쓰임
  - 각 단계 안에서는 여전히 "선호 근무 지역"과 일치하는 공고를 앞쪽으로 정렬
