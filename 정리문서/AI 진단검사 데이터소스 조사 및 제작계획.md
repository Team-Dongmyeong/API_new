# AI 진단검사(진로·기업핏·인성) 데이터 소스 조사 및 제작 계획 정리

## 1. 조사 목적 및 배경
- **목적:** 프론트엔드 AI 진단검사 3종(진로검사, 기업핏검사, 인성검사)을 구축하기 위해, 기존 공개 설문지를 그대로 가져다 쓸 수 있는지 / 공공데이터를 활용해 직접 만들어야 하는지 조사.
- **동시 진행:** 채용공고 연동을 잡코리아·사람인 + **원티드(Wanted) OpenAPI**까지 신청.
- **전제:** 이번 학기 담당 파트인 채용공고 UI/UX 작업과 별개로, 프론트엔드에 들어갈 "AI 진단검사" 화면을 위한 데이터·문항 소스를 확보하는 단계.

---

## 2. 검토 결과: 기존 설문지 "그대로 가져오기"는 불가능

### 2-1. 검토한 방법
- 워크넷 직업선호도검사, 커리어넷 진로심리검사, NCS 직무능력진단 등 기존에 공개된 검사 문항을 스크래핑해서 가져오고, 결과값 계산(채점) 로직만 우리 서비스에 맞게 수정하는 방식을 검토.

### 2-2. 불가능하다고 판단한 이유
| 사유 | 상세 내용 |
|---|---|
| **저작권 문제** | 표준화된 검사 문항은 대부분 저작물로 보호됨. 채점 로직만 바꾸고 문항 문장을 그대로 쓰는 것도 "그대로 베낀 것"에 해당해 저작권 침해 소지가 있음 |
| **기술적 차단** | 실제로 ncs.go.kr 페이지를 프로그램으로 가져오려 시도했을 때 `robots.txt`로 접근 자체가 차단되어 있음을 확인 — 명시적인 스크래핑 금지 정책 |
| **논문 특성상 문제** | 본 프로젝트는 졸업논문이며, "직접 설계한 진단 알고리즘"이 핵심 기여점임. 기존 검사를 그대로 가져오면 독창성이 없어지고 표절 시비로 이어질 수 있어 심사에 불리 |

### 2-3. 결론
기존 설문지를 그대로 가져오는 방식은 폐기하고, **공공데이터포털에서 확보한 NCS(국가직무능력표준) 데이터를 재료로 삼아 문항을 직접 제작**하는 방향으로 결정.

---

## 3. NCS 데이터 기반 진로검사 제작 절차 (상세 6단계)

공공데이터포털에서 신청·승인 완료한 "한국산업인력공단_NCS 기준정보 조회" API(대분류/중분류/소분류/세분류 코드 조회, 능력단위분류코드 조회, 능력단위요소 조회, 능력단위키워드 검색 — 총 7개 오퍼레이션)를 활용한 제작 절차는 다음과 같음.

| 단계 | 작업 내용 | 비고 |
|---|---|---|
| **1단계: 매핑** | 우리가 정의한 37개 세부직무를 NCS 세분류(직무) 코드에 하나씩 연결 | 1:1로 정확히 안 맞는 직무는 가장 가까운 세분류로 수작업 매칭 필요 |
| **2단계: 재료 수집** | 매핑된 세분류마다 능력단위·능력단위요소 목록을 API로 조회 | "이 직무는 이런 일을 할 수 있어야 한다"는 원문 텍스트 확보 |
| **3단계: 문항화** | 능력단위요소 문장("~하기")을 자기보고식 설문 문항("나는 ~하는 것을 좋아한다/자신 있다" 등, 5점 척도)으로 직접 재작성 | 자동 변환 불가 — 팀원이 직접 각색해야 하는 핵심 작업 |
| **4단계: 문항-직무 태깅** | 문항마다 어떤 세부직무(혹은 대분류)에 가중치를 주는지 태깅 | 기존 `PreferenceQuiz.jsx`의 선택지별 `category` 태깅 패턴과 동일한 구조 |
| **5단계: 채점 로직 설계** | 응답을 세부직무별 점수 벡터로 환산하는 계산식 설계 | 현재 `PreferenceContext`의 `toVector()`는 대분류 5개 기준이라, 세부직무(37개) 단위까지 진단하려면 구조 확장 필요 |
| **6단계: 검증** | 소규모 팀 내 테스트로 문항 신뢰도(비슷한 응답이 반복되는지) 점검 | 문항 수가 많아질수록 필요성 커짐 |

## 4. 검사 종류별 데이터 소스 및 진행 상태

| 검사 종류 | 데이터 소스 | 확보 상태 | 비고 |
|---|---|:---:|---|
| **진로검사** | NCS 세분류·능력단위·능력단위요소 (공공데이터포털 API) | **확보 완료** | 자동승인, 인증키 발급받음 → 바로 문항화 작업 착수 가능 |
| **기업핏검사** | NCS 직업기초능력 10개 영역 자료 (공공데이터포털, 파일 형태) | **위치만 파악, 다운로드 필요** | 승인 절차 없이 즉시 다운로드 가능한 자료 — API처럼 신청·승인을 거친 상태는 아직 아님 |
| **인성검사** | 미정 | **보류** | NCS와 결이 다른 영역(성격 특성 측정)이라 별도 설계 필요, 우선순위 후순위로 미룸 |

---

## 5. 채용공고 API(원티드) 신청 현황
- 잡코리아·사람인 + **원티드(Wanted) OpenAPI**까지 채용공고 연동 신청을 진행함.
- 원티드 OpenAPI는 Jobs API(포지션 목록/필터), Companies API(기업별 채용 포지션) 등을 제공.
- **승인 방식이 자동승인이 아님**: 신청 접수일 기준 **영업일 3일 이내** 심사 후 이메일로 인증키가 발급되는 구조.
- **현재 상태: 신청 완료, 승인 대기 중.** 메일함에서 인증키 발급 여부를 확인해야 함 — "신청함"과 "승인받아 키를 받음"은 다른 상태이므로 혼동하지 않도록 주의.

## 6. 우선순위 및 다음 작업

### 6-1. 우선순위
1. **진로검사** — 재료(NCS API) 확보 완료, 가장 먼저 착수
2. **기업핏검사** — 재료 위치 파악 완료, 다운로드 후 진로검사와 유사한 절차로 진행
3. **인성검사** — 후순위, 별도 이론(예: Big5) 기반 설계는 추후 진행

### 6-2. 체크리스트
- [x] NCS 데이터 공공데이터포털 활용신청 (자동승인 완료)
- [x] 원티드 채용공고 API 신청
- [ ] 원티드 API 승인/인증키 발급 여부 확인
- [ ] 37개 세부직무 ↔ NCS 세분류 코드 매핑표 작성
- [ ] NCS 직업기초능력 10개 영역 자료 다운로드
- [ ] 진로검사 문항 초안 작성 (NCS 능력단위요소 기반)
- [ ] 기업핏검사 문항 초안 작성 (직업기초능력 10개 영역 기반)
- [ ] 채점 로직 설계 — `PreferenceContext` 세부직무(37개) 단위로 확장 검토
- [ ] 인성검사는 별도 착수 시점에 재논의

---

## 7. 결론
진로검사·기업핏검사 모두 기존 설문지를 가져다 쓰는 방식은 저작권·논문 독창성 문제로 배제했고, 대신 NCS 공공데이터(API + 다운로드 자료)를 원재료로 삼아 문항을 직접 제작하는 방향으로 확정했다. NCS 쪽 데이터 확보는 마쳤으므로 다음 단계는 매핑표 작성과 문항화 작업이며, 원티드 채용공고 API는 신청 후 승인 대기 상태로 별도 확인이 필요하다. 인성검사는 당장 착수하지 않고 진로검사·기업핏검사 완료 이후로 미룬다.
